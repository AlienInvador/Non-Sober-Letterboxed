## Findings for files I was told not to edit

The other agent owns these files. Each finding gives the file and line, the problem and the exact fix.

### components/log-sheet.tsx

1. **:59, closing timer is never cleared (bug).** `setTimeout(() => setOpen(false), 1400)` is not stored. Save a sesh, close the sheet, and open it again within 1.4 s: the new sheet closes on its own. Fix: keep the timer in a `useRef`, then call `clearTimeout(ref.current)` inside `open()` and in an unmount cleanup.
2. **:48, :52, the sheet has no exit and the scrim does not fade.** The sheet slides in for the tw-animate default of 150 ms and then disappears instantly on close. Fix: use the same classes as `components/send-rec.tsx` (changed in this pass). Overlay: `duration-300 ease-out-soft data-[state=open]:animate-in data-[state=open]:fade-in data-[state=closed]:animate-out data-[state=closed]:fade-out data-[state=closed]:duration-200`. Content: `duration-300 ease-out-soft data-[state=open]:animate-in data-[state=open]:slide-in-from-bottom data-[state=closed]:animate-out data-[state=closed]:slide-out-to-bottom data-[state=closed]:duration-200`.
3. **:66-70 and :217-221, two signals for one save, and the live region may not be read.** A toast "Logged" and an in-sheet "Logged." both appear. The toast's `role="status"` element is mounted with its text already inside it, and screen readers often skip live regions added that way. Fix: show the toast only when the sheet auto-closes (`autoClose === true`). Keep the toast's `role="status"` wrapper always mounted and render only the text conditionally.
4. **:218, the done state ignores reduced motion.** Motion animations run in JS, so the global CSS reduced-motion rule does not stop them. Fix: `const reduce = useReducedMotion()` and `initial={reduce ? false : { scale: 0.98, opacity: 0 }}`.
5. **:243, stale search results.** `if (!q.trim()) return` leaves the old results on screen after the field is cleared. Fix: `if (!q.trim()) { setResults([]); setFailed(false); return }`.
6. **:265-267, fake listbox (a11y).** `role="listbox"` with `role="option" aria-selected={false}` buttons promises arrow-key navigation that does not exist. Fix: remove both roles and keep a plain list of buttons, or build it on `cmdk` the way `command-palette.tsx` does. There is also no "No matches" line when a search returns nothing. Add one: `results.length === 0 && q.trim() && !failed`.
7. **:177, contrast.** `text-faint` on the `raised` sheet is 3.55:1. Fix: `text-muted`.
8. **:223, contrast.** `text-accent` on `raised` is 2.87:1. Fix: `text-note`. The same swap was made everywhere else in this pass.
9. **:207, the review field has no label.** Its only label is the placeholder. Fix: wrap it as `<label className="flex flex-col gap-1 text-sm text-muted">Review (optional)<textarea … /></label>` and drop the placeholder.
10. **:76, inputs are 14 px.** `field` uses `text-sm`, so iOS Safari zooms in on focus for every select and textarea in the sheet. Fix: `text-base` in `field`.
11. **:171, hyphen used as a minus.** `'- More' : '+ More'`. Fix: label it "More" with lucide `ChevronDown` (`aria-hidden`, `className={more ? 'rotate-180' : ''}`, `transition-transform duration-200`).
12. **:148 and :161, small targets.** "Change" and "I was sober" are text-sm underlined text about 20 px tall. Fix: add `min-h-10 px-2 -mx-2` to each.
13. **:229-231, Save has no press state, ASCII dots, and no reason when disabled.** "Saving..." should be "Saving…". Add the `press` class (now in `globals.css`). When `canSave` is false only because of `crewMissing`, show "Pick a crew to share with" next to the button.
14. **:21, LogButton has no press state.** Fix: add `press` to the className.
15. **:84 and :170, hidden companions.** A tag approval presets `companionIds`, but "More" starts closed, so the person cannot see who is attached. Fix: `useState(!!preset.companionIds?.length)` for `more`.

### components/session-card.tsx

16. **:37, contrast.** The influence line is tinted with `style={{ color }}`. Drunk on `bg` is 4.33:1 at text-sm, which fails AA. Fix: drop the inline color, use `text-body` and let `InfluenceDot` carry the color. The Tonight queue tiles and the profile legend were changed the same way in this pass.
17. **:11-13, rules duplicated.** `WHEN` repeats `stateWord` from `lib/influence.ts`, and `verdict` repeats `verdict()` there with different capitalization. Fix: `` `${i.recommend ? 'Recommends it' : 'Would skip it'} ${stateWord(i.influence)}` `` and delete `WHEN`.
18. **:42, off-scale size.** `text-[17px]` is a one-off. Fix: `text-base` (the movie page reviews use 16 px with the same leading).
19. **:23-27 and :35, two targets for the title.** The poster links to the movie but the title does not. Fix: wrap the `h3` text in the same `Link`, then give the poster link `tabIndex={-1} aria-hidden` and an image with `alt=""` so keyboard users get one stop per card.
20. **:20, stagger length.** No change needed. `.rise` delays are now capped at the 6th item in `globals.css`, so a 20-card feed no longer waits 665 ms on the last card.

### app/auth/login/page.tsx

21. **:35, no pending state (bug).** A double click sends two OTP emails, and the second often comes back as Supabase's rate-limit error. Fix: `const [pending, setPending] = useState(false)`. Set it before the request and clear it on error. Add `disabled={pending}` and the `press disabled:opacity-60` classes.
22. **:33, autofill and radius.** Add `autoComplete="email"` and replace `rounded-xl` with `rounded-control`, matching gate and onboarding.
23. **:25, wrong eyebrow.** "welcome back" greets first-time visitors too, and every new user lands here after the gate. Fix: a line that is true for both, for example "one link, no password" (or whatever fits the password-login rewrite).
24. **:28, dead-end success state.** It says "Check your email for a magic link." with no address and no way back. Fix: "We sent a link to {email}." plus a text button "Use a different email" that resets `sent`.
25. **:16, raw provider errors.** `error.message` shows Supabase text such as "For security purposes, you can only request this after 52 seconds". Fix: map `error.status === 429` to "Give it a minute, then send a new link."

### app/auth/callback/route.ts

26. **:19, silent failure.** An expired or used link redirects to `/auth/login` with no explanation. Fix: redirect to `/auth/login?error=link` and have the login page show "That link expired. Send a new one."

### lib/queries/

27. **Speed (all of `lib/queries/*`), repeated auth calls.** One Tonight load calls `auth.getUser()` about 7 times, and each call is a network round trip to Supabase Auth: `getHittingTonight`, `getFeed`, `getQueue`, `getHero`, `getRecsForMe`, `getTagsForMe`, plus the page itself. Add the layout and the middleware on top. It also runs the same friendships query 3 times through `peopleFilter`. Fix: one `lib/queries/ctx.ts` with `export const ctx = cache(async () => …)` and `export const friendIds = cache(async (me) => …)` (React `cache`, which memoizes per request). Then replace the local `ctx()` and `peopleFilter` copies in `feed.ts`, `crews.ts`, `lists.ts`, `discover.ts`, `movie.ts`, `tags.ts`, `recs.ts` and `profile.ts`.
28. **profile.ts:36 and :67, wrong total (bug).** The sessions query has `.limit(200)` and `total: items.length`, so anyone with more than 200 seshes sees "200 seshes", and the influence breakdown only covers their latest 200. Fix: add a `select('id', { count: 'exact', head: true }).eq('user_id', p.id)` to the `Promise.all` and use its count for `total`. The breakdown should come from the same unlimited count per influence, or from a grouped view.
29. **movie.ts:23-24, popular movies lose reviews (bug).** Public reviews and "your people watched it" are both taken from the newest 100 readable sessions. On a popular movie, older public reviews and friends' watches disappear. Fix: run two queries. One gets reviews (`.eq('visibility','public').not('review','is',null).limit(50)`). The other gets friends (`.in('user_id', friendIds)`).
30. **feed.ts:96-115, the hero can show the wrong state.** When the hero comes from `hitting[0]`, `mine` is searched only in the latest 50 recommended rows. If it is missing there, `influence` falls back to `'both'` and the hero shows a "both" percentage that nobody may have logged. Fix: when `hitting[0]` is used, fetch its latest recommended session directly: `.eq('tmdb_id', pick).eq('recommend', true).or(people).order('created_at',{ascending:false}).limit(1)`.
31. **feed.ts:35, your own pick sold as your people's.** `peopleFilter` includes `me`, so the hero eyebrow "your people's pick tonight" can point at your own sesh. Fix: exclude `me` in `getHero` (`.neq('user_id', me)`) or change the copy.
32. **tags.ts:21-30, needless wait.** Two independent queries run one after the other. Fix: run them in one `Promise.all`.

## What I changed elsewhere

- `app/globals.css`: `.rise` stagger is capped at the first 6 items (`min(var(--i), 5)`). Reduced motion also zeroes `animation-delay`, so staggered items no longer sit invisible. `.font-display` tracking went from -0.025em to -0.01em and moved into `@layer components`. Before that move, the unlayered rule silently beat every `tracking-*` utility on the landing headings. Large headings now set their own tracking. Added `text-wrap: balance` on headings and `pretty` on paragraphs (in `@layer base`), plus a `.press` utility (scale .96 on `:active`, 150 ms).
- Contrast: every `text-accent` text (2.87 to 3.66:1) is now `text-note` in the recs and tags inboxes, the command palette retry, "New list…", and the profile request count. `text-faint` on raised surfaces is now `text-muted` in send-rec and movie-actions. The influence-tinted small text on Tonight queue tiles and the profile legend is now `text-body`, with the color on the dot only. The Discover percentage grew to 24 px, which makes it large text: drunk passes at 4.33:1, and the number is the answer on that screen.
- Cheers button: dropped the hover-only `opacity-60`. It failed contrast and never showed on touch. The cheered state is now `bg-selected`. Added press feedback. The 🥂 stays as the product's one signature.
- Motion: the send-rec sheet now enters and exits like a sheet, with a scrim on the same clock (300 ms in, 200 ms out). The Add to list popover scales in from its trigger (150 ms, `zoom-in-95`). Influence chips and primary and secondary buttons got press feedback. PosterTile no longer runs JS (`useReducedMotion`) just to pick a hover class. It uses `motion-safe:` instead, and the `hover:scale` is gone.
- Deleted: PosterTile's unused `influence` badge prop (never passed, 10 px text).
- Bugs: the friends search ignores stale responses, so a slow "ab" result can no longer overwrite "abc". Onboarding has a pending state, so a double submit no longer flashes "That username is taken" after success. When the sesh delete is armed, focus moves to Cancel, so keyboard users are not dropped to `<body>`. The queue Remove button is disabled while pending.
- Forms: added `autoComplete` (`bday`, `username`) to gate and onboarding, plus `autoCapitalize="none"` and no spellcheck on the username. Input radius is now the `rounded-control` token.
- Layout: profile and friends pages use the same gutter as every other page (`px-6 py-8 md:px-10`, centered), not `p-10`. The mobile tab bar respects the iOS safe area, and its tabs are at least 44 px tall. Nav rail links got hover color.
- Copy: removed the fabricated "— couch club" testimonial attribution, so the line reads as the product's own note. "maya" in the landing mock became "jules". Changed "..." to "…". The error page no longer says "try again" twice.
- Tokens: the marquee waves use `fill-accent-fill`, not a hard-coded hex.

## Ponytail-audit findings I did not fix

What this repo does: a Next.js 15 app on Supabase where 21+ users log movies they watched drunk or high, tag friends, share with crews and see recommend percentages per state. Assumed load: small social app, tens to low thousands of users, one region.

Security is in good shape. RLS covers every table: `friendships` only lets you update `status`, and you cannot self-accept. Tag inserts must be `pending`. Redirect targets go through `safeNext`. The feed cursor is regex-checked before it reaches PostgREST.

Must fix:

1. **Error text fails contrast** (`design/tokens.ts`, `--color-drunk` used as `text-drunk` in about 15 places). Errors are 4.33:1 on `bg` and 3.39:1 on sheets. I did not change it, because tokens were out of scope. Fix: add an error text token, for example `#FF6FA8` (5.84:1 on bg, 4.57:1 on raised), and keep `#FF2E88` for dots and bars.
2. **Items 21, 28 and 29 above** (login double submit, profile total capped at 200, movie page dropping reviews) are real bugs in the other agent's files.

Should fix:

3. **Repeated auth round trips** (item 27). This is the biggest speed win. On top of it, `lib/supabase/middleware.ts:54` runs one profile query per navigation, and `app/(app)/page.tsx:24-26` fetches the username again although the layout already has it. Not fixed: the fix belongs in `lib/queries/` and the auth flow, which the other agent is rewriting.
4. **The `me()` helper is copied 4 times** (`actions/crews.ts`, `friends.ts`, `lists.ts`, `queue.ts`), and recs, sessions, tags and cheers inline the same three lines. Fix: one `lib/supabase/me.ts`. Not fixed: it touches every action file while auth is being reworked, so it would create merge conflicts.
5. **The friends search calls a server action (2 queries) on every keystroke** (`components/friends-client.tsx:31`). Stale responses are now ignored, but there is no debounce. Fix: a 250 ms debounce like the one in `command-palette.tsx`.

Nice to have:

7. **The command palette has no "no results" state** and no visible trigger other than Ctrl+K (`components/command-palette.tsx`).
8. **`actions/queue.ts:34`: `removeFromQueue` does not check that `tmdbId` is an integer**, unlike `toggleQueue`. Harmless, because the delete is scoped to the user's id.

Verdict: healthy. Fix the error-text token and items 21, 28 and 29 first.

Not checked: e2e and DB tests (the local Supabase is in use by the other agent). Motion was not scrubbed frame by frame in a browser. No screenshots were taken, because the app needs a seeded Supabase to render past the gate.
